Go Programming বাংলায় | Beginner থেকে Production-Level

১. Conditional Statement কী?
Conditional statement হলো এমন একটি programming structure, যা কোনো condition-এর ফলাফল অনুযায়ী নির্দিষ্ট code চালায়।
ধরো, তোমার Ticket Booking API-তে একজন user ticket কিনতে চায়। তুমি যাচাই করবে:

- User logged in কি না
- Ticket-এর quantity সঠিক কি না
- পর্যাপ্ত ticket আছে কি না
- Payment সম্পন্ন হয়েছে কি না
  এসব সিদ্ধান্ত নিতে conditional statement ব্যবহার করা হয়।
  Condition পরীক্ষা করো
  যেমন: age >= 18

true
if block
Condition সত্য হলে

false
else block
Condition মিথ্যা হলে

Go-তে condition-এর ফলাফল true অথবা false হয়। JavaScript-এর মতো condition-এর মধ্যে arbitrary truthy/falsy value ব্যবহার করা যায় না।
উদাহরণস্বরূপ:
if age >= 18 {
fmt.Println("Eligible")
}

এটি সঠিক। কিন্তু if age {} সঠিক নয়, কারণ age একটি integer, boolean নয়।

২. if Statement
if ব্যবহার করা হয় যখন কোনো condition সত্য হলেই শুধু একটি কাজ করতে হবে।
package main

import "fmt"

func main() {
age := 22

    if age >= 18 {
        fmt.Println("You are an adult")
    }

}

Output:
You are an adult

Code ব্যাখ্যা

- age := 22 — একটি integer variable তৈরি হয়েছে।
- age >= 18 — পরীক্ষা করা হচ্ছে age ১৮ বা তার বেশি কি না।
- Condition true হওয়ায় if block-এর code execute হয়েছে।
  গুরুত্বপূর্ণ নিয়ম
  Go-তে { একই লাইনে condition-এর পরে থাকবে।
  সঠিক:
  if age >= 18 {
  fmt.Println("Eligible")
  }

সাধারণ Go formatting অনুযায়ী gofmt এই style বজায় রাখে। Brace অন্য লাইনে শুরু করার চেষ্টা করলে Go-এর automatic semicolon insertion-এর কারণে syntax error হতে পারে।

৩. if...else Statement
যখন condition সত্য হলে একটি কাজ এবং মিথ্যা হলে অন্য কাজ করতে হবে, তখন else ব্যবহার করবে।
package main

import "fmt"

func main() {
balance := 300

    if balance >= 500 {
        fmt.Println("You can purchase this ticket")
    } else {
        fmt.Println("Insufficient balance")
    }

}

Output:
Insufficient balance

এখানে balance ৩০০, কিন্তু প্রয়োজন ৫০০। তাই if condition মিথ্যা এবং else block execute হয়েছে।
Flow বোঝো
balance >= 500

True
Purchase allowed

False
Insufficient balance

৪. if...else if...else
যখন একাধিক condition পরীক্ষা করতে হবে, তখন else if ব্যবহার করা যায়।
ধরো, exam-এর marks অনুযায়ী grade নির্ধারণ করবে।
package main

import "fmt"

func main() {
marks := 82

    if marks >= 80 {
        fmt.Println("Grade: A+")
    } else if marks >= 70 {
        fmt.Println("Grade: A")
    } else if marks >= 60 {
        fmt.Println("Grade: A-")
    } else if marks >= 50 {
        fmt.Println("Grade: B")
    } else if marks >= 40 {
        fmt.Println("Grade: C")
    } else {
        fmt.Println("Grade: F")
    }

}

Output:
Grade: A+

Condition-এর order কেন গুরুত্বপূর্ণ?
ধরো, তুমি এভাবে লিখলে:
if marks >= 40 {
fmt.Println("Grade: C or above")
} else if marks >= 80 {
fmt.Println("Grade: A+")
}

যদি marks = 82 হয়, প্রথম condition-ই সত্য হবে। ফলে দ্বিতীয় condition আর পরীক্ষা করা হবে না।
Senior Engineer tip: একাধিক range condition থাকলে এমন order ব্যবহার করবে, যাতে সবচেয়ে নির্দিষ্ট বা উচ্চ threshold আগে পরীক্ষা হয়। অথবা domain rule অনুযায়ী পরিষ্কারভাবে range সাজাবে।

৫. Comparison Operators
if ও switch-এ condition তৈরি করতে comparison operators ব্যবহার করা হয়।
Operator অর্থ উদাহরণ
== সমান age == 18
!= সমান নয় status != "paid"

>     বড়	price > 100
>
> < ছোট quantity < 5
> = বড় অথবা সমান age >= 18
> <= ছোট অথবা সমান stock <= 0
> উদাহরণ:
> package main

import "fmt"

func main() {
stock := 0

    if stock <= 0 {
        fmt.Println("Out of stock")
    }

    if stock != 10 {
        fmt.Println("Stock is not 10")
    }

}

Output:
Out of stock
Stock is not 10

খেয়াল রাখবে, = assignment-এর জন্য এবং == comparison-এর জন্য ব্যবহৃত হয়।

৬. Logical Operators — &&, ||, !
অনেক সময় একাধিক condition একসঙ্গে যাচাই করতে হয়।
AND — &&
সব condition সত্য হতে হবে।
age := 22
hasID := true

if age >= 18 && hasID {
fmt.Println("Access allowed")
}

OR — ||
অন্তত একটি condition সত্য হলেই হবে।
isAdmin := false
isModerator := true

if isAdmin || isModerator {
fmt.Println("Can moderate content")
}

NOT — !
Boolean condition-এর ফলাফল উল্টে দেয়।
isBlocked := false

if !isBlocked {
fmt.Println("User is not blocked")
}

Short-circuit evaluation
Go-তে && এবং || short-circuit evaluation ব্যবহার করে।
if user != nil && user.IsActive {
fmt.Println("Active user")
}

যদি user == nil হয়, তাহলে দ্বিতীয় condition পরীক্ষা করা হবে না। ফলে user.IsActive access করে nil pointer panic হওয়ার ঝুঁকি এড়ানো যায়।
এটি কেবল তখনই কাজ করে যখন প্রথম condition সঠিকভাবে nil পরীক্ষা করে এবং expression-এর বাকি অংশে নিরাপদে access করা সম্ভব হয়।

৭. if-এর Short Statement
Go-এর একটি বিশেষ সুবিধা হলো if condition-এর আগে ছোট initialization statement লেখা যায়।
package main

import (
"fmt"
"strconv"
)

func main() {
input := "123"

    if number, err := strconv.Atoi(input); err == nil {
        fmt.Println("Number:", number)
    } else {
        fmt.Println("Invalid number:", err)
    }

}

Output:
Number: 123

এখানে strconv.Atoi() string-কে integer-এ convert করার চেষ্টা করছে।

- Conversion সফল হলে err == nil সত্য হয়।
- Conversion ব্যর্থ হলে else block চলে।
- number ও err variable-দুটি if...else statement-এর scope-এর মধ্যে থাকে।
  ধরো, input := "abc" করলে conversion ব্যর্থ হবে এবং error branch execute হবে।
  Production-এ এটি কেন কাজে লাগে?
  API request থেকে ID বা quantity string আকারে এলে validation-এর আগে integer-এ convert করতে হতে পারে।
  if quantity, err := strconv.Atoi(input); err != nil {
  fmt.Println("Invalid quantity")
  } else if quantity <= 0 {
  fmt.Println("Quantity must be positive")
  } else {
  fmt.Println("Valid quantity:", quantity)
  }

তবে বাস্তব HTTP API-তে শুধু fmt.Println() করলেই হবে না। উপযুক্ত status code এবং structured response দিতে হবে।

৮. switch Statement
যখন একটি variable বা expression-এর বিভিন্ন নির্দিষ্ট value অনুযায়ী আলাদা কাজ করতে হবে, তখন switch খুব উপকারী।
ধরো, ticket-এর payment status হতে পারে:

- pending
- paid
- failed
- refunded
  অনেকগুলো if...else if লেখার পরিবর্তে switch ব্যবহার করলে code পরিষ্কার হয়।
  package main

import "fmt"

func main() {
status := "paid"

    switch status {
    case "pending":
        fmt.Println("Payment is pending")

    case "paid":
        fmt.Println("Payment successful")

    case "failed":
        fmt.Println("Payment failed")

    case "refunded":
        fmt.Println("Payment refunded")

    default:
        fmt.Println("Unknown payment status")
    }

}

Output:
Payment successful

কীভাবে কাজ করে?

1. switch status — status-এর value পরীক্ষা করা হচ্ছে।
2. case "pending" — value pending হলে এই block চলবে।
3. case "paid" — value paid হলে এই block চলবে।
4. default — কোনো case match না করলে এটি চলবে।
   Go-এর গুরুত্বপূর্ণ নিয়ম: সাধারণ Go switch-এ একটি case execute হওয়ার পর স্বয়ংক্রিয়ভাবে পরের case-এ চলে যায় না। JavaScript বা C-এর প্রচলিত switch pattern-এর সঙ্গে এটি একটি গুরুত্বপূর্ণ পার্থক্য।

৯. একাধিক Value-র জন্য একটি case
একই ধরনের একাধিক value-তে একই কাজ করতে চাইলে একটি case-এ সেগুলো একসঙ্গে লিখতে পারো।
package main

import "fmt"

func main() {
day := "Friday"

    switch day {
    case "Friday", "Saturday":
        fmt.Println("Weekend")

    case "Sunday", "Monday", "Tuesday", "Wednesday", "Thursday":
        fmt.Println("Working day")

    default:
        fmt.Println("Invalid day")
    }

}

Output:
Weekend

এখানে শুক্রবার ও শনিবারকে একই category-তে রাখা হয়েছে।
এ ধরনের pattern status, role, category এবং user permission-এর মতো logic-এ কাজে লাগে।

১০. Expression ছাড়া switch
Go-তে switch-এর মধ্যে কোনো expression না লিখেও condition ব্যবহার করা যায়। এটি অনেকটা if...else if-এর বিকল্প।
package main

import "fmt"

func main() {
score := 76

    switch {
    case score >= 80:
        fmt.Println("Grade A+")

    case score >= 70:
        fmt.Println("Grade A")

    case score >= 60:
        fmt.Println("Grade A-")

    case score >= 40:
        fmt.Println("Pass")

    default:
        fmt.Println("Fail")
    }

}

Output:
Grade A

এখানে প্রতিটি case একটি Boolean expression। উপর থেকে নিচে condition পরীক্ষা হয়, প্রথম matching case-টি execute হয়।
if...else নাকি switch?
পরিস্থিতি উপযুক্ত পছন্দ
এক বা দুটি সাধারণ condition if...else
একাধিক range condition if...else if বা expressionless switch
একটি variable-এর নির্দিষ্ট value switch
একাধিক status-এর জন্য আলাদা behavior switch
Error check ও early return সাধারণত if
কোনটি বেছে নেবে, সেটি readability এবং business logic-এর ওপর নির্ভর করবে।

১১. fallthrough কী?
Go-তে default behavior হলো matching case execute করে switch থেকে বেরিয়ে যাওয়া। তবে fallthrough ব্যবহার করলে পরের case-এর body-ও execute করা যায়, পরের case-এর condition সত্য কি না তা পরীক্ষা না করেই।
package main

import "fmt"

func main() {
number := 1

    switch number {
    case 1:
        fmt.Println("One")
        fallthrough

    case 2:
        fmt.Println("Two")

    default:
        fmt.Println("Other")
    }

}

Output:
One
Two

এখানে number হলো 1, তবুও fallthrough-এর কারণে case 2-এর body execute হয়েছে।
Senior Engineer-এর পরামর্শ
সাধারণ business logic-এ fallthrough খুব কমই প্রয়োজন হয়। এটি code-এর flow বোঝা কঠিন করতে পারে, তাই পরিষ্কার বিকল্প থাকলে সেটি ব্যবহার করবে।

১২. Type Switch
কখনো interface-এর ভেতরে কোন ধরনের value আছে, সেটি যাচাই করতে হয়। তখন type switch ব্যবহার করা যায়।
package main

import "fmt"

func describe(value any) {
switch v := value.(type) {
case string:
fmt.Println("String:", v)

    case int:
        fmt.Println("Integer:", v)

    case bool:
        fmt.Println("Boolean:", v)

    default:
        fmt.Printf("Other type: %T\n", v)
    }

}

func main() {
describe("Zamirul")
describe(100)
describe(true)
describe(3.14)
}

Output:
String: Zamirul
Integer: 100
Boolean: true
Other type: float64

এখানে any কী?
any হলো Go-তে interface{}-এর alias। এটি যেকোনো type-এর value ধারণ করতে পারে।
func describe(value any)

এখানে function-টি যেকোনো type-এর argument নিতে পারে।
Type switch কীভাবে কাজ করে?
switch v := value.(type)

- value হলো interface value।
- value.(type) শুধু type switch-এর case-এ ব্যবহার করা যায়।
- প্রতিটি case নির্দিষ্ট type পরীক্ষা করে।
- v matching case-এর মধ্যে সেই type-এর value হিসেবে ব্যবহার করা যায়।
  Production tip: any সুবিধাজনক হলেও সবকিছু any দিয়ে গ্রহণ করলে compile-time type safety কমে যায়। সম্ভব হলে নির্দিষ্ট type বা interface ব্যবহার করবে। Type switch প্রয়োজনমতো ব্যবহার করো, অপ্রয়োজনীয়ভাবে প্রতিটি value-এর type পরীক্ষা করতে নয়।

১৩. Real-World Project: Ticket Booking Validation
এখন আমরা একটি ছোট কিন্তু বাস্তবসম্মত business rule implement করব।
ধরো, একটি event-এ ticket বুক করতে হলে:

1. Event অবশ্যই active হতে হবে।
2. Quantity অবশ্যই positive হতে হবে।
3. Requested quantity available stock-এর বেশি হতে পারবে না।
4. Payment status paid হতে হবে।
   প্রথমে আমরা একটি validation function লিখি।

package main

import (
"errors"
"fmt"
)

type BookingRequest struct {
EventActive bool
Quantity int
Available int
PaymentStatus string
}

func ValidateBooking(req BookingRequest) error {
if !req.EventActive {
return errors.New("event is not active")
}

    if req.Quantity <= 0 {
    	return errors.New("quantity must be positive")
    }

    if req.Quantity > req.Available {
    	return errors.New("not enough tickets available")
    }

    switch req.PaymentStatus {
    case "paid":
    	return nil

    case "pending":
    	return errors.New("payment is pending")

    case "failed":
    	return errors.New("payment failed")

    default:
    	return errors.New("invalid payment status")
    }

}

func main() {
req := BookingRequest{
EventActive: true,
Quantity: 2,
Available: 10,
PaymentStatus: "paid",
}

    if err := ValidateBooking(req); err != nil {
    	fmt.Println("Booking rejected:", err)
    	return
    }

    fmt.Println("Booking validation successful")

}

Expected output:
Booking validation successful

এই code-এর কিছু ভালো দিক:

- Invalid request-এর জন্য error return করা হয়েছে।
- Payment status-এর জন্য switch ব্যবহার করা হয়েছে।
- main()-এর business logic সহজে পড়া যায়।
  কিন্তু production-এ যাওয়ার আগে কয়েকটি বিষয় ঠিক করতে হবে:
- Available এবং Quantity শুধু validation করা হচ্ছে; concurrent booking-এর সময় stock race condition এড়াতে database transaction বা atomic inventory strategy দরকার।
- Payment status client-এর request থেকে সরাসরি বিশ্বাস করা যাবে না। Payment provider বা server-side payment record থেকে যাচাই করতে হবে।
- Error-গুলোকে নির্দিষ্ট sentinel error বা typed error হিসেবে সাজানো যেতে পারে।
- Unit tests এবং integration tests যোগ করতে হবে।
- Validation সফল হলেই booking সম্পন্ন হয়েছে, এমন নয়। এটি শুধু business rules-এর প্রাথমিক পরীক্ষা।
  মনে রাখবে: Validation এবং booking execution দুটি আলাদা বিষয়। Production system-এ শুধু validation করে ticket reserve করা নিরাপদ নয়।

১৪. Common Mistakes — যেগুলো এড়াবে
Mistake 1
else ভুল লাইনে লেখা
Go-তে closing brace-এর পরে else একই statement-এর অংশ হিসেবে লিখতে হবে।
if age >= 18 {
fmt.Println("Adult")
} else {
fmt.Println("Minor")
}

Mistake 2
ভুল condition order
score >= 40 আগে পরীক্ষা করলে score >= 80-এর branch-এ পৌঁছানো যাবে না, যদি প্রথম branch-এর মধ্যে return বা অন্য কোনো flow control না থাকে।

Mistake 3
switch-এ automatic fallthrough ধরে নেওয়া
Go-তে সাধারণত matching case শেষ হলে switch থেকে বেরিয়ে যায়। প্রয়োজন ছাড়া fallthrough যোগ করবে না।

Mistake 4
Security check-এ শুধু client input বিশ্বাস করা
isAdmin, paymentStatus বা isPaid-এর মতো value client পাঠালে সেগুলো সরাসরি অনুমোদনের ভিত্তি হিসেবে ব্যবহার করবে না। Server-side verification দরকার।
